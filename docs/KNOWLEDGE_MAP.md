## 1 · 位姿与坐标系

**一句话**：说"在哪"必须先说"相对谁"；位姿 = 位置 + 姿态。

```bash
rkin pose --xyz 0.4 0.2 0.3 --rpy 0 0 90
```

看点：
- `R = Rz(yaw)·Ry(pitch)·Rx(roll)` —— 顺序写反结果完全不同
- 点 (0.1, 0, 0) 变换后是 **(0.4, 0.3, 0.3)**（先转 90°，再平移；忘了转就是错的）
- 同一姿态的四种写法（矩阵 / RPY / 轴角 / 四元数）互相重建，偏差 < 1e-12

📖 `core/rotations.py` 顶部注释写了全部约定；`core/se3.py` 里 `__mul__` 的注释解释了"为什么顺序不能反"。

---

## 2 · 变换链

**一句话**：把"相机里表达的量"换成"本体里表达的量"。

```bash
rkin cam --all
```

看点（实测数字）：

| 算例 | 杯子在 base 下的位置 |
|---|---|
| 基准 | `[0.7830, 0.1634, 0.8]` |
| 杯子在相机里 x 变大 | `[0.9562, 0.2634, 0.8]` |
| 相机 yaw 改成 0° | `[0.8, -0.1, 0.8]` |

**杯子一动没动** —— 变的是"用什么语言描述它"。这就是坐标变换的全部含义。

---

## 3 · 正运动学

**一句话**：关节角 → 末端位置。**永远有解，且唯一。**

```bash
rkin fk --q1 0 --q2 90      # → (1, 1)
rkin panda-fk --case ppt_goal
```

看点：
- 二连杆：`x = L1cos(q1) + L2cos(q1+q2)`，第二段的角度是**两段相加**
- 同一个 FK 也能写成变换链：`Rz(q1)·Tx(L1)·Rz(q2)·Tx(L2)`
- Panda 的 ETS（URDF 写法）与 MDH（教材写法）是**两套独立实现**，FK 逐位相等

---

## 4 · 逆运动学

**一句话**：末端位置 → 关节角。**可能多解、可能无解、可能无穷多解。**

```bash
rkin ik --target 1 1                  # 两组解：肘上 / 肘下
rkin ik --target 3 0                  # 无解（够不着，不是 bug）
rkin panda-ik --case ppt_goal         # 7 自由度：数值迭代 + 冗余
```

看点：
- 二连杆有闭式解（余弦定理），Panda 只能数值迭代（阻尼最小二乘 ≈ 牛顿法）
- **IK 求出解必须送回 FK 验算** —— 命令输出里那张表的最后一列就是这件事
- 无解是物理限制，本项目用 `UnreachableTargetError` 把它和真正的错误分开

---

## 5 · 雅可比

**一句话**：末端微调 ↔ 关节微调。它是 FK 的导数，**只在小步时成立**。

```bash
rkin jac --q1 0 --q2 90 --dx 0 0.1
```

看点：
- `J = [[-1,-1],[1,0]]`，解 `J·Δq = [0, 0.1]` 得 `Δq = [0.1, -0.1] rad = [5.73°, -5.73°]`
- 两个关节**配合着动**（一个正转、一个反转），手才往上走
- 拿 0.5 m 的大位移去试，误差立刻就出来了 —— 局部线性化的边界

📖 在 `pick` 流水线里雅可比是**干活的**：第 ⑦ 道工序用它算"压 1mm 要多少度关节角"。

---

## 6 · 奇异点

**一句话**：某个方向上的瞬时运动能力**丧失**了。`det(J)=0`，物理上就是手臂伸直了还想往外挪。

```bash
rkin sing              # 四姿态扫描表
rkin jac --q1 0 --q2 0 --dx 0 0.1   # 奇异位姿：明确报错而不是返回巨大解
```

看点（实测）：

| q2 | 90° | 30° | 10° | 1° |
|---|---|---|---|---|
| cond(J) | 2.62 | 9.36 | 28.58 | inf |
| 最坏方向放大倍数 1/σ_min | 1.62 | 4.33 | 12.83 | 128.12 |

越接近伸直，同样的末端动作就需要越夸张的关节速度 —— 真机上就是抖、跳、停机。

---

## 7 · 冗余与零空间

**一句话**：7 个关节对 6 维任务 → 至少 1 维"不动末端也能动关节"的方向。

```bash
rkin panda-ik --case ppt_goal --prefer-config 0 -0.3 0 -2.2 0 2.0 0.8
```

看点（实测，也是本项目踩过的坑）：
- 让解靠近理想姿态，实际只缩短了 **0.00019 rad**，而"能动分量"看着有 0.0227
- 差别在**夹角**：偏好方向与零空间接近正交时，能动分量再大也几乎不缩短距离
- 所以在 `pick` 流水线里，这一项是**评分的一部分**（离偏好位形 0.2 的权重），
  而不是唯一的优化目标 —— 权重写在 `pick.SCORE_WEIGHTS` 里，可审计

---

## 8 · 真机约束：关节限位与"末端是哪个坐标系"

**一句话**：数学上算得出来的姿态，真机不一定摆得出来；同一个"末端"，不同工具的定义能差 10 cm。

```bash
rkin panda-fk --case zero               # 法兰帧：0.9260
rkin panda-fk --case zero --frame tcp   # 夹爪帧：0.8226（与课件日志一致）
```

看点（实测）：
- 法兰 → 夹爪 TCP = 再往前 **103.4 mm** 并绕 z 转 **-45°**
- 课件 `run_logs` 记的是夹爪 TCP（`robot.fkine` 的默认行为），本项目默认给法兰帧
- **两边都没错** —— 对不上时第一件事是问"末端是哪个坐标系"，而不是怀疑公式
- 另外：课件的"全零姿态"越过了 q4 的关节限位，是一个数学参考位形，真机摆不出来

## 把七个知识点串起来：抓取流水线

七个知识点不是七个并列的工具，而是**一条工序链上的七道工序** —— 把任何一道拿掉，这件事就做不成。

| # | 工序 | 知识点 | 拿掉它会怎样 |
|---|---|---|---|
| ① | 观测 → 本体位姿 | 位姿与坐标系、变换链 | 不知道该抓哪 |
| ② | 可达性预筛 | 工作空间不是球 | 白算一场，且失败原因说不清 |
| ③ | 多初值 IK | IK 的多解 / 无解 / 数值迭代 | 没有可执行的东西 |
| ④ | 雅可比体检 | 雅可比与奇异点 | 真机会抖、跳、撞 |
| ⑤ | 限位校验 | 真机约束（关节限位） | 解出来也执行不了 |
| ⑥ | 解择优 | 冗余与零空间 | 可能挑到贴限位、转两圈多的解 |
| ⑦ | 微动可行性校验 | 雅可比**干活**：解一次小位移 | 雅可比沦为只看不用的摆设 |

第 ⑦ 道是刻意加的：抓取前总要"往下压一点再合爪"，这一步算的就是
"末端压 1mm，关节要动多少度" —— 算出来大得离谱，说明这组解在实际中不能用。

```bash
rkin pick --observe 0.2 0 0 --plot     # 一条命令跑完七道工序，并出一张任务图
rkin pick --observe 0.35 -0.05 0.15 --arm planar   # 二连杆跑同一条流水线
```

### 失败也是一等公民

demo 只演示成功路径；这条流水线把失败也变成**有名字、有数字**的结论：

| 结论 | 会给出的信息 |
|---|---|
| `不在工作空间` | 沿该方向可达 1.11 m，目标 1.13 m，差多少、以及"换初值没用" |
| `姿态不可达` | 位置有余量、但姿态做不到，最佳残差多少，并建议换个抓取姿态 |
| `收敛精度不足` | 差一点就能收敛：最佳残差 vs 要求，以及"换更多初值或放宽精度" |
| `所有解越关节限位` | 有几组解、越限位几组、越了多少 |
| `所有解接近奇异` | σ_min 区间、最难运动的方向 |
| `微动不可行` | 末端动 1mm 需要多少度关节角、上限是多少 |

外加一类成功 `可执行`（附关节解、离限位余量、σ_min、离初始位形多远、残差）。

**验证过的例子** —— 同一位置，只换一个抓取姿态，结论完全不同：

```bash
rkin pick --observe 0.35 -0.05 0.15 --rpy 180 0 0   # 姿态不可达（位置够、方向做不到）
rkin pick --observe 0.35 -0.05 0.15 --rpy 0 90 0    # 可执行
```
