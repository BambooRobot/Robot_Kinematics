**把这一章串成一个任务**：`rkin pick` —— 七道工序、六类失败结论。
七道工序与六类失败结论见 [`KNOWLEDGE_MAP.md`](KNOWLEDGE_MAP.md)。

**和课件脚本的关系**：课件那套实验（12 个扁平脚本）里有几件事值得改：

1. **同一个公式抄了好几份**：`fk` 在 03/05/11 各一份，`jacobian` 在 06/07/11 各一份。
   一旦改了公式就得记得四处都改 —— 本项目把数学收进 `core/`，一份实现。
2. **关键的数学是调库的**：`SE3.Trans`、`robot.fkine`、`robot.ikine_LM` 都来自
   `spatialmath` / `roboticstoolbox`。能用，但你看不到里面在算什么。
   本项目把 SE3、FK、IK、雅可比全部自己写了一遍。
3. **`panda_cases.csv` 没被任何脚本读**：声明了却闲置。本项目把它接进批量报告。

⚠️ **本项目不复用课件的代码，但严格复用课件的数值**：PPT 上的算例、
`run_logs/` 里记录的库输出，全部变成了 `tests/` 里的断言（见 `docs/NUMBERS.md`）。
所以"自己写一遍"不是放飞，而是拿同一把尺子量。

## 第 1 章 · 先补三个概念

### 1.1 位姿 = 位置 + 姿态；坐标系回答"相对谁"

说"杯子在 (0.5, -0.1, 0.2)"是没有意义的 —— **相对谁**？

- `camera_link`：相机看到目标时用的坐标系
- `base_link`：机器人本体的基座坐标系（机械臂规划认这个）
- `tool0`：末端工具坐标系

同一句话必须带上坐标系才有意义：`^camera p_cup = (0.5, -0.1, 0.2)`。
而**位姿**比位置多一层：不只是"在哪里"，还有"朝哪边"。
抓紧杯子时，只知道杯子中心点不够，还得知道夹爪该从哪个方向靠近。

数学上把这两件事绑成一个 4×4 矩阵：

```
    ┌             ┐
    │   R    t   │      R = 3×3 旋转（姿态）
T = │             │      t = 3×1 平移（位置）
    │  0 0 0  1  │
    └             ┘
```

这就是 `SE3`（三维刚体变换）。★ **核心用途只有一个**：
把"B 坐标系下的量"换成"A 坐标系下的量"，写作 `^A T_B`。

### 1.2 FK 与 IK：一个正向、一个反向

| | 输入 | 输出 | 什么时候用 |
|---|---|---|---|
| **FK**（正运动学） | 每个关节的角度 q | 末端位姿 | 想知道"手现在在哪" |
| **IK**（逆运动学） | 目标位姿 | 关节角 q | 想抓东西 —— 人先知道目标在哪，不知道关节角 |

这里有个必须建立的直觉：**FK 永远有唯一答案，IK 不一定**。

- IK 可能**多解**：二连杆把末端送到 (1,1)，可以肘朝上，也可以肘朝下（两组解）。
- IK 可能**无解**：目标太远（超出 L1+L2）或太近（内圈的洞），物理上够不着。
- IK 可能**无穷多解**：Panda 有 7 个关节，末端只有 6 个自由度 —— 多出来的 1 个自由度叫**冗余**，
  同一个位姿有无穷多组关节角。

### 1.3 雅可比：末端微调 ↔ 关节微调

到底了时手臂伸得笔直，让末端再往外挪一点点 —— 关节该怎么动？
答案是"几乎动不了"，因为再往外只能靠把手臂**拉长**，而它拉不长。这就是**奇异点**。

雅可比 J 描述的就是这个局部关系：

```
Δx ≈ J(q) · Δq          末端小位移 = 雅可比 × 关节小转角
```

- 它**只在小步时成立**（是当前姿态下的线性近似）。
- 它**依赖当前姿态**：同一个机械臂，姿态不同 J 就不同。
- 二连杆的 J 是 2×2；Panda 的是 6×7（末端 6 个自由度、7 个关节）。
- `det(J) = 0`（或最小奇异值 = 0）就是奇异位姿：某个方向上的瞬时运动能力**丧失**了。

## 第 2 章 · 先跑起来，再读代码

### 2.1 不装依赖也能跑

核心数学只需要 numpy，不需要课件那两个库：

```bash
cd robot_kinematics_app
pip install -e .

PYTHONPATH=src python3 -m robotkinematics check
# 或者 pip install -e . 之后直接用 rkin 命令
```

`rkin check` 会告诉你环境缺什么。看到 `环境检查完成，可以开始实战。` 就可以继续。

### 2.2 五条命令看完全貌

```bash
rkin cam --case ppt_case        # ① 坐标变换链：杯子在相机里 → 在本体里
rkin fk  --q1 0 --q2 90         # ② 二连杆 FK：末端到 (1, 1)
rkin ik  --target 1 1           # ③ 同一件事反过来：两组解，各自 FK 回验
rkin jac --q1 0 --q2 90 --dx 0 0.1   # ④ 末端挪 0.1 m，关节该转多少
rkin panda-fk --case ppt_goal   # ⑤ 换成 7 自由度的真实机械臂，同一套路子
```

再跑 `rkin batch`，它会把 `data/cases/` 里所有算例一次跑完并落盘到 `outputs/`。

### 2.3 出图

```bash
rkin panda-fk --case ppt_goal --plot     # 骨架图 → outputs/panda_fk_pose.png
rkin anim --sweep q2 --frames 60         # 关节扫动 → outputs/two_link_sweep_q2.gif
```

⚠️ 如果你的机器上绘图输出的是"三视图"而不是 3D 图，说明本机 matplotlib 的 3D 模块坏了
（系统与 pip 各装了一份 matplotlib，老的 `nspkg.pth` 把 `mpl_toolkits` 指到了老目录）。
命令会在 stderr 说明原因和修法 —— **数值不受影响，只是换了种画法**。


## 第 4 章 · 一次坐标变换的一生

用 `rkin cam --case ppt_case` 把全过程走一遍。场景：相机装在本体上，斜着 30° 看桌面，
杯子出现在相机视野的 (0.5, -0.1, 0.2) 处。

**第一步：相机相对本体在哪？**

```
^base T_camera = Trans(0.30, 0, 0.60) · Rz(30°)
```

读作："相机装在本体前方 0.3 m、上方 0.6 m，并且绕本体 z 轴转了 30°"。

**第二步：杯子相对相机在哪？**

```
^camera T_cup = Trans(0.5, -0.1, 0.2)
```

**第三步：合起来。**

```
^base T_cup = ^base T_camera · ^camera T_cup
```

⚠️ **顺序不能反**。读成一句话：
"杯子现在在**相机**里表达，而机械臂需要它在**本体**里表达，所以乘 `^base T_camera`。"

算出 `t = [0.7830, 0.1634, 0.8]` —— 这就是机械臂要抓的位置。

**第四步：为什么改了参数数值就变？**

`rkin cam --all` 会把练习 1 的三种变化跑出来：

| 算例 | 改了什么 | 杯子在 base 下的位置 |
|---|---|---|
| ppt_case | —（基准） | `[0.7830, 0.1634, 0.8]` |
| change_x | 杯子在相机里 x: 0.50 → 0.70 | `[0.9562, 0.2634, 0.8]` |
| change_y | 杯子在相机里 y: -0.10 → 0.20 | `[0.6330, 0.4232, 0.8]` |
| yaw_zero | 相机 yaw: 30° → 0° | `[0.8, -0.1, 0.8]` |

★ **关键理解**：同一个物理目标，换一个坐标系表达，数值就变了 —— **杯子一动没动**。
"坐标变换"从不是改变物体，而是改变**描述**。

## 第 6 章 · NumPy / Python 特性速查

| 用法 | 说明 | 例子 |
|---|---|---|
| `np.deg2rad` | 度 → 弧度。**忘记它是最常见的错误** | `q = np.deg2rad(90)` |
| `@` | 矩阵乘法（不是 `*`） | `R = rotz(y) @ roty(p) @ rotx(r)` |
| `np.linalg.solve(A, b)` | 解 Ax = b，比 `inv(A) @ b` 更稳更快 | `dq = np.linalg.solve(J, dx)` |
| `np.linalg.svd` | 奇异值分解。`compute_uv=False` 只要奇异值 | `sigma = np.linalg.svd(J, compute_uv=False)` |
| `np.linalg.pinv` | 伪逆，能处理奇异矩阵（最小范数解） | 零空间投影必须用它 |
| `np.clip` | 夹到区间内，避免 `arccos` 收到 1.0000000002 | `np.clip(cos_q2, -1, 1)` |
| `np.cross` | 叉乘 | `np.cross(z_i, p_ee - p_i)` |
| `@dataclass(frozen=True)` | 不可变值对象；本项目用它表达模型与结果 | `Planar2R(l1, l2)` |
| `field(default_factory=...)` | dataclass 的可变默认值必须这样写 | `tool: SE3 = field(default_factory=SE3.identity)` |
| `Protocol` | 结构化类型："只要有 fk 和 jacobian 就行" | `ik_solvers.PoseSource` |
| `zip(a, b, strict=True)` | 长度不等时立刻报错，不用等算到一半才发现 | 关节数与角数要对齐 |
| `np.set_printoptions` | 控制打印精度 | 见各脚本开头 |

## 第 7 章 · 数学的坑

### 7.1 角度与弧度混用 ⚠️

课件里那句提醒是真的：`q = 90` 在 NumPy 里是 90 **弧度**（≈5157°）。
症状是结果"看起来像那么回事但完全不对"。
本项目所有内部计算用弧度，只在**打印**和**命令行参数**上用度，转换点只有 `np.deg2rad` / `np.rad2deg`。

### 7.2 变换顺序写反 ⚠️

`A · B` 与 `B · A` 不是一回事。记住读法：
"这个目标现在在 X 里表达，下一步需要它在 Y 里表达 → 乘 `^Y T_X`。"

### 7.3 万向锁

RPY 的 pitch 到 ±90° 时，roll 与 yaw 只能确定它们的**组合**，无法分开。
本项目约定此时 `roll = 0`，把角度全记在 yaw 上 —— 不是为了好看，
而是让结果**可复现**。真正需要无歧义时用四元数。

### 7.4 奇异点不是错误，是物理限制

`det(J) = 0` 时解不出关节微调量，但 FK 照样正常。区别在于：
- 位姿本身没问题（`rkin fk` 照样出数）
- "往某个方向再挪一点"这个**动作**做不了

所以本项目在奇异点抛的是 `SingularPoseError`（一个可预期的领域异常），
而不是让程序崩在 `np.linalg.solve` 上。

### 7.5 7 自由度为什么有无穷多解

6 维任务 + 7 个关节 = 至少 1 维零空间。沿零空间方向动关节，末端**纹丝不动**。
工程上这是优点：多出来的自由度可以用来避障、远离关节限位、让姿态更舒服。
`rkin panda-ik --prefer-config q1 q2 … q7` 就是用它把解拉向指定姿态。

⚠️ **但别高估它的效果**（这一条是实测踩出来的）：

```bash
rkin panda-ik --case ppt_goal --seed 0 0 0 0 0 0 0 \
              --prefer-config 0 -0.3 0 -2.2 0 2.0 0.8
```

实测：到参考姿态的距离 4.2113 rad → 4.2111 rad，实际只缩短 **0.00019**，
而"能动分量" `|N·(q_ref−q)|` 有 0.0227。两个数差两个数量级，原因是：

- `|N·d|` 是"偏好里**能动**的那部分"，不是"能缩短的距离"；
- 距离能缩短多少，取决于这点分量与整条差值向量的**夹角**。本例两者接近正交，
  于是能动分量存在，却几乎不改变距离。

**教训**：先算 `|N·d|` 和它的夹角，再决定这个次要任务值不值得做。
代码里对应 `ik_solvers.nullspace_improvement_bound()`。

### 7.6 数值精度的坑（本项目实际踩过）

用 `arccos((tr-1)/2)` 求旋转角，**小转角**时条件数爆炸：1e-15 的舍入误差能让结果偏差百分之几，
IK 的收敛精度会悄悄劣化。正确写法是用 `atan2(‖反对称部‖/2, (tr−1)/2)`。
**是"解析雅可比 vs 数值微分"这条测试抓出来的**（偏差 3e-2 → 修完 9e-10）。

### 7.7 "末端"到底是哪个坐标系（本项目最大的一个坑）

同一个机器人、同样的关节角，不同工具算出的末端位置能差 10 cm —— 因为它们对"末端"的定义不同。

本项目实测（`rkin crosscheck`，对照 roboticstoolbox 1.4.3）：Panda 全零姿态下

| 谁 | 末端位置 |
|---|---|
| 法兰 `panda_link8`（URDF 的最后一个连杆） | `[0.088, 0, **0.926**]` |
| 夹爪 TCP（法兰 + 103.4mm + 绕 z 转 45°） | `[0.088, 0, **0.8226**]` |

差的那 0.1034 m 不是算错，而是 roboticstoolbox 的 Panda 模型**自带夹爪**，
`robot.fkine(q)` 默认返回夹爪 TCP。课件日志用的是默认末端，所以记的是 0.8226。

⚠️ 我最初还犯过一个更隐蔽的错：看到"日志的数值"和"日志里打印的 ETS 表"对不上，
就断言"日志自相矛盾"。实际上 ETS 表描述的是机器人本体（到法兰），
`fkine` 又静默地接了夹爪偏移 —— 表没错，日志也没错，是我读了半张表就下结论。

**教训**：跟别人的运动学结果对不上时，**先问"末端是哪个 frame"**，
再怀疑公式。本项目为此提供了两个帧：

```bash
rkin panda-fk --case zero              # 法兰帧（默认）
rkin panda-fk --case zero --frame tcp  # 夹爪 TCP 帧，与课件日志一致
```

另外，雅可比也会跟着末端帧变（线速度部分含"末端到关节的杠杆臂"）——
对照时两端必须用同一个帧，否则连雅可比都会"不一致"。

### 7.8 实现层面的坑（写代码时才暴露的）

上面几条是**数学**上的坑，这一条是**写代码**时才暴露的 —— 都是做 `rkin pick` 流水线时实际踩到的：

1. **多圈解**：数值 IK 曾给出二连杆 `q = (-13.6, 15.1) rad` —— 运动学完全正确，
   真机却要转两圈多。修法：择优时默认偏好"离初始位形近"的解。
   教训：**"解出来了"和"能执行"是两件事**。
2. **任务残差 ≠ 完整位姿误差**：二连杆没有姿态自由度，如果拿完整 6 维误差去判定，
   会把"位置解得很好"误判为失败（实测残差显示成 1.45）。修法：区分"任务残差"与完整位姿误差。
3. **工序编号与执行顺序不一致**：报告里一度出现 ①②③④⑦⑤⑥ —— 读的人会以为是错的。
   修法：限位校验（候选过滤）放到择优之前、微动校验（终检）放到最后。
4. **不收敛时白跑迭代**：目标不可达时求解器会跑满 400 次迭代才放弃。
   修法：`solve_dls` 加停滞检测（连续 20 轮残差无改善即放弃该初值），
   最慢的测试从 14.9 s 降到 5.3 s。

> 这几条都留了注释和测试。它们的共同点是：**只有把东西跑起来才会暴露**，
> 光看公式看不出来 —— 这也是为什么这个项目坚持"每个知识点都要有一条命令能验证"。

## 第 8 章 · 动手实验

⚠️ 下面的结果全部是**实测值**，不是推测。改完参数请自己复核一遍。

### 实验 A · 关节角怎么决定末端位置

```bash
rkin fk --q1 0 --q2 90      # tool = [1.0000, 1.0000]
rkin fk --q1 30 --q2 60     # tool = [0.8660, 1.5000]
rkin fk --q1 60 --q2 -30    # tool = [1.3660, 1.3660]
rkin fk --q1 0 --q2 0       # tool = [2.0000, 0.0000]  ← 完全伸直
```

**观察**：`q2 = 0°` 时末端到原点的距离 = L1 + L2 = 2.0，这是工作空间的**外边界**。

### 实验 B · 同一个目标点，两组姿态

```bash
rkin ik --target 1 1
```

结果：`(0°, 90°)` 与 `(90°, -90°)` —— 肘上 / 肘下。
把 `--target` 换成 `(2, 0)`（正外边界）会出现什么？（提示：两组解会**退化**成一组。）

### 实验 C · 换个连杆比例看"洞"

```bash
rkin --l1 1 --l2 0.3 ik --target 0.5 0
```

`L1 ≠ L2` 时原点附近出现够不着的**内圈**（内半径 |L1−L2| = 0.7）。
这是二连杆工作空间最反直觉的一点。

### 实验 D · 奇异点前关节速度的放大

```bash
rkin jac --q1 0 --q2 90 --dx 0 0.001     # dq 很小
rkin jac --q1 0 --q2 1  --dx 0 0.001     # dq 大得多
```

实测放大倍数（= 1/σ_min，即"最坏方向"上末端走 1 m 需要多大的关节转角）：

| q2 | 90° | 30° | 10° | 1° |
|---|---|---|---|---|
| 1/σ_min | 1.62 | 4.33 | 12.83 | 128.12 |

**同样的末端位移，越接近奇异点，需要的关节速度越大** —— 这就是实际机器人
在奇异点附近"抖""跳"的原因。（注意这是所有方向里**最坏**的那个；某个固定方向的
放大倍数并不随 q2 单调，取决于它与奇异方向的夹角。）

### 实验 E · Panda 的冗余（以及次要任务的真实收益）

```bash
rkin panda-ik --case ppt_goal                # 看"冗余"那一节：不同初值 → 不同关节角
rkin panda-ik --case ppt_goal --seed 0 0 0 0 0 0 0 \
              --prefer-config 0 -0.3 0 -2.2 0 2.0 0.8
```

第二条命令让解尽量靠近指定的参考姿态。实测结果（**与直觉相反，值得一看**）：

| | 与 q_ref 的距离 | 末端位置误差 |
|---|---|---|
| 不加次要任务 | 4.2113 rad | 6.9e-11 m |
| 加了次要任务 | 4.2111 rad | 1.2e-16 m |

只缩短了 0.00019 rad。报告里会打印"能动分量 0.0227 rad"和"估算上限 0.00006 rad"——
**能动分量不等于能缩短的距离**，详见第 7.5 节。

### 实验 F · 让 IK 失败

```bash
rkin panda-ik --pose 3 0 0 0 0 0
```

目标远在工作空间之外。观察：程序**没有崩**，而是明确报出"未收敛 + 残差 + 可能原因"。
这就是 `NotConvergedError` 存在的意义。

### 实验 G · 改配置 vs 改命令行

编辑 `configs/default.yaml` 把 `planar.l1` 改成 0.5，然后：

```bash
rkin fk --q1 0 --q2 0                    # 用配置里的 0.5
rkin fk --l1 1.0 --q1 0 --q2 0           # 命令行覆盖成 1.0（结果 2.0）
```

验证一下你有没有理解优先级。

## 第 9 章 · 卡住时怎么办

### 9.1 三个最容易卡住的地方

1. **忘了 `np.deg2rad`** —— 结果离谱先查这个。
2. **变换顺序写反** —— 结果"像对的但差一点"。用 `rkin cam --case ppt_case` 对照标准答案。
3. **奇异位姿下解方程** —— 报 `SingularPoseError`。这不是 bug，是让你知道该换个姿态。

### 9.2 加打印

```bash
rkin fk --q1 0 --q2 90        # 末端位置、det(J)、可达范围一次全出来
rkin panda-jac --case ik_seed # 6×7 雅可比 + cond + 可操作度
```

数值之外想看过程，就在 `tests/` 里加一条断言 —— 本项目所有数都从测试里来的。

### 9.3 常见运行错误

| 报错 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: No module named 'robotkinematics'` | 没设 PYTHONPATH 也没安装 | `PYTHONPATH=src python3 -m robotkinematics …` 或 `pip install -e .` |
| `错误: 目标 (3.0, 0.0) 超出二连杆的工作空间` | IK 无解（物理限制） | 换一个可达的目标，或加大 L1/L2 |
| `错误: 配置项 "plaenar.l1" 无法识别` | 配置里拼错了 | 按提示改拼写；这条告警是故意留的 |
| `错误: 配置项 planar.l1=-1 超出允许范围` | 配置值不合法 | 连杆长度必须为正 |
| `未收敛（200 次迭代后残差 …）` | IK 不收敛 | 换初值、放宽 `--tol`、或确认目标可达 |
| 3D 图变成三视图 | 本机 matplotlib 的 3D 模块坏了 | 见 README「已知环境问题」 |

## 附录 · 一分钟速查

**关键公式**

```
R = Rz(yaw)·Ry(pitch)·Rx(roll)          本项目与课件统一的 RPY 约定
^A T_B = [ R  t ; 0 0 0 1 ]             齐次变换矩阵
p_A = R·p_B + t                         点变换
^A T_C = ^A T_B · ^B T_C                变换链（顺序不能反）
x = L1cos(q1) + L2cos(q1+q2)            二连杆 FK
y = L1sin(q1) + L2sin(q1+q2)
cos(q2) = (x²+y²-L1²-L2²)/(2L1L2)       二连杆 IK（± 对应肘上/肘下）
det(J) = L1·L2·sin(q2)                  二连杆雅可比行列式
Δx ≈ J(q)·Δq                            雅可比：局部线性
dq = Jᵀ(JJᵀ + λ²I)⁻¹e                   阻尼最小二乘 IK
```

**关键数字**

- 二连杆算例：`fk(0°,90°) = [1,1]`、`ik(1,1) = (0°,90°) / (90°,-90°)`、`J = [[-1,-1],[1,0]]`
- 奇异点：`det(J) = 0` @ q2 = 0° / 180°；`cond(J)` = 2.62 / 9.36 / 28.58 @ q2 = 90°/30°/10°
- 坐标变换：`^base T_cup.t = [0.7830, 0.1634, 0.8]`
- Panda：7 关节、6×7 雅可比、连杆 0.333 / 0.316 / 0.384 / 0.0825 / 0.088 / 0.107 m

**关键命令**

```bash
rkin pick --observe 0.2 0 0                 抓取任务：七道工序一条命令
rkin check                                  环境自检
rkin cam --all                              坐标变换链全部算例
rkin fk/ik/jac/sing                         二连杆
rkin panda-fk/-ik/-jac/-sing                Panda
rkin batch                                  批量报告 → outputs/
rkin crosscheck                             与真库对照（需可选依赖）
pytest -q                                   265 条断言
```

**依赖规则**：`cli` 是组合根可依赖全部；`usecases` 只许依赖 `core` 与 `contracts`；
**用例不许直接依赖 `adapters`**（重构前 8 条边，现在 0 条）。
